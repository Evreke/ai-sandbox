## pi-delegate: оркестрация воркеров для pi — ищем тестировщиков

Написал расширение для pi, которое превращает одного агента в руководителя команды. Нужны люди, у которых есть pi и готовность помять это на своих задачах.

**Что это.** Вы описываете задачу и роли — оркестратор сам раскладывает её на части, пишет брифы, спавнит воркеров (каждый в своём worktree), собирает отчёты. Ритуал спавна, который раньше приходилось держать в голове (и иногда забывать), скомпилирован в один вызов `delegate`. Пока воркеры пашут — занимаетесь своим; вотчер разбудит, когда кто-то закончил, сломался или задал вопрос.

Коротко о главном:

- **неблокирующий спавн** — вызов отпускает через ~15 с, воркер продолжает работать;
- **вотчер** — будит по событиям: отчёт готов / воркер спросил / контекст на исходе / воркер умер;
- **почтовый ящик** — можно докинуть уточнения уже запущенному воркеру;
- **строгие отчёты** — JSON со схемой и file:line, «done» не считается;
- **бюджеты и градусники** — ctx% и токены видны вживую, превышение блокирует перезапуск;
- **fleet-оверлей** — `/delegate-fleet` показывает всех живых воркеров разом;
- **автоуборка** — после успешного сбора отчёта воркер сам закрывается.

Прошёл обкатку на реальных задачах: диагностика и оптимизация медленного конвейера тестов (параллельный фан-аут), фича, построенная пятью воркерами за вечер.

## Что нужно от вас

1. **Поставить.** Скопировать или symlink: `pi/extensions/pi-delegate/` → `~/.pi/agent/extensions/pi-delegate/`.
2. **Настроить тиры** — одна строка в `~/.pi/agent/pi-delegate.config.json`:
   ```json
   {
     "tiers": { "flash": { "provider": "...", "model": "..." } },
     "defaults": { "tier": "flash" }
   }
   ```
   Без конфига будет ошибка `E_TIER` с подсказкой — так и задумано.
3. **Прогнать свои задачи.** Лучше всего заходят: мультифайловые правки, рефакторинги, исследования кодовой базы, ревью, генерация тестов. Начните с одного воркера, потом фан-аут из 2–3.
4. **Написать, что сломалось или бесит** — сюда: [ссылка на issues]. Особенно ценно:
   - оркестратор повёл себя глупо (скиньте скрин переписки);
   - отчёт пришёл невалидный или воркер «сделал» без отчёта;
   - непонятно из текста ошибки, что делать дальше;
   - fleet-оверлей показывает ерунду.

## Чего ждать не стоит

- В npm пока не опубликовано — сначала ваши находки.
- Это не автономный «менеджер проектов»: решения и мерж — за вами.
- Первый запуск лучше делать на некритичном репо (воркеры пишут в ветки, но обкатка есть обкатка).

Вопросы и находки — в комментарии или issues. Скрины fleet-оверлея с живыми воркерами особенно приветствуются.
